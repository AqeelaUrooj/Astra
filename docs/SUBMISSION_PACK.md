## Project title

**ASTRA — Explainable Crew-Health Trends with Offline Telemetry Resilience**

## Short description

ASTRA is a prototype mission-health dashboard designed around two operational needs: making changes in health-related telemetry easier to inspect and preserving queued telemetry during a simulated communications outage. It visualizes synthetic heart-rate, blood-oxygen, sleep, and exercise readings; compares recent and earlier windows; surfaces transparent data-quality checks and rule-based observations; and demonstrates local store-and-forward synchronization when a simulated link returns.

## Problem

During long-duration space missions, crew members may need to understand changes in health-related indicators while communications with ground teams are delayed or interrupted. A useful monitoring interface should make data quality, trend evidence, and connectivity state visible rather than presenting unexplained status labels.

## Proposed solution

ASTRA combines a dashboard, descriptive trend comparisons, explainable prototype rules, and a communications-outage demonstration. When the simulated link is paused, the browser can queue synthetic packets locally. When the link is restored, the app sends the queue to a FastAPI endpoint that validates packets and avoids writing duplicate packet IDs twice. A cached dashboard snapshot helps demonstrate continuity when fresh API data is unavailable.

## What is distinctive

- **Evidence beside observations:** each rule-based observation provides its supporting values and a rule identifier.
- **Data quality is visible:** the analysis panel shows engineering checks rather than hiding data-quality assumptions.
- **Connectivity is part of the workflow:** outage, queueing, retry, and synchronization can be demonstrated end-to-end.
- **Limitations are explicit:** the interface labels generated readings as synthetic and avoids presenting the output as a medical diagnosis.

## Data and scientific integrity statement

The dashboard uses **synthetic telemetry generated by the application**. ASTRA v0.6 introduced a live, read-only search of NASA OSDR study metadata to help users discover relevant research records. It does not download, ingest, analyze, or reproduce measurement files from those studies, and it does not feed OSDR records into the crew telemetry or alert engine. All numeric rules are illustrative engineering examples, not medically validated thresholds, NASA operational standards, or approved crew-health procedures. ASTRA v0.7 also includes a mission event timeline that combines synthetic telemetry checkpoints and generated observations with browser-local simulated communications and synchronization events. These are not real spacecraft logs. ASTRA is not intended for clinical use or real mission decisions.
